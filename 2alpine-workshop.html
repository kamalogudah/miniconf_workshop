Core Directives

x-data · x-text · x-html · x-bind

EX 2.1 x-data & x-text — Declaring State x-data · x-text ▼

x-data turns any element into a reactive Alpine component by defining its state as a plain JS object. x-text sets an element's text content to a reactive expression — equivalent to Vue's {{ }} mustaches or React's {variable} in JSX. No manual DOM updates needed — the DOM stays in sync automatically.

HTML
<!-- x-data declares the component and its state -->
<div x-data="{ name: 'World', year: 2024 }">

  <!-- x-text sets inner text reactively -->
  <h2>Hello, <span x-text="name"></span>!</h2>
  <p   x-text="'Year: ' + year"></p>

  <!-- jQuery equivalent (you'd do this on every change): -->
  // $('#name').text(name); ← manual, error-prone

</div>

EX 2.2 x-bind — Dynamic Attributes x-bind · :class · :style · :disabled ▼

x-bind:attr (shorthand: :attr) dynamically sets any HTML attribute to a reactive expression. Use :class for toggling CSS classes, :style for inline styles, :href, :disabled, :src — anything. Identical to Vue's v-bind.

HTML
<div x-data="{ active: false, color: '#b8f55a' }">

  <!-- Toggle a CSS class dynamically -->
  <button :class="active ? 'btn-lime' : 'btn-ghost'"
          @click="active = !active">
    Toggle Active
  </button>

  <!-- Bind a style object -->
  <div :style="{ backgroundColor: color }"></div>

  <!-- Conditionally disable an input -->
  <input :disabled="!active" />

</div>

Reactivity & State

Counters, computed values, x-effect

EX 3.1 Counter — The "Hello World" of Reactive UI x-data · x-text · @click ▼

In jQuery you'd manually run $('#el').text(count) on every change. In Alpine the DOM is always a pure reflection of state — the same mental model as React's useState or Vue's ref(), but written directly in HTML.

Alpine.js vs jQuery
<!-- ✅ Alpine — state drives the DOM -->
<div x-data="{ count: 0 }">
  <button @click="count--">−</button>
  <span   x-text="count"></span>
  <button @click="count++">+</button>
</div>

<!-- ❌ jQuery — manual DOM on every change -->
let count = 0;
$('#plus').on('click',  () => { count++; $('#c').text(count); });
$('#minus').on('click', () => { count--; $('#c').text(count); });

EX 3.2 x-effect — Side Effects on State Change x-effect ▼

x-effect re-evaluates an expression every time any reactive data it references changes — Alpine's equivalent of React's useEffect(fn, [dep]) or Vue's watchEffect(). Use it for logging, syncing localStorage, analytics, or triggering imperative code.

HTML
<div x-data="{ price: 100, qty: 1 }"
     x-effect="console.log('Total updated:', price * qty)">

  Price: <input type="number" x-model.number="price" />
  Qty:   <input type="number" x-model.number="qty"   />
  Total: <span   x-text="'$' + (price * qty).toFixed(2)"></span>

</div>

Events & Interactions

x-on / @ · .prevent · .stop · .once · keyboard modifiers

EX 4.1 Event Listeners & Modifiers @click · .prevent · .once · @keyup.enter ▼

x-on:event (shorthand @event) attaches event listeners. Modifiers are dot-suffixes: .prevent calls preventDefault(), .stop calls stopPropagation(), .once auto-removes after first fire, .debounce.300ms delays, .outside fires when click is outside the element. Keyboard: @keyup.enter, @keydown.escape.

HTML
<div x-data="{ log: [] }">

  <!-- .prevent calls e.preventDefault() -->
  <a href="#" @click.prevent="log.unshift('Link prevented')">Click</a>

  <!-- .once: listener removed after first fire -->
  <button @click.once="log.unshift('Fired once!')">Once</button>

  <!-- Keyboard modifier -->
  <input @keyup.enter="log.unshift('Enter pressed')" />

  <!-- .outside: fires when click is outside this div -->
  <div @click.outside="log.unshift('Clicked outside')">...</div>

</div>

Lists & Conditions

x-for · x-if · x-show

EX 5.1 To-Do List — x-for, x-if, x-show x-for · x-if · x-show ▼

x-for renders a block for each item in an array (like Vue's v-for or React's .map()) — it requires a <template> wrapper. x-if completely removes the element from the DOM when false (no hidden node). x-show toggles CSS display — keeping the element in the DOM. Use x-if for expensive components; x-show for quick toggles.

HTML
<div x-data="{ todos: [{ t:'Learn Alpine', d:false }], input:'' }">

  <input x-model="input"
         @keyup.enter="todos.push({ t: input, d: false }); input = ''" />

  <!-- x-for needs a <template> -->
  <template x-for="(todo, i) in todos" :key="i">
    <div :class="todo.d ? 'done' : ''">
      <input type="checkbox" x-model="todo.d" />
      <span  x-text="todo.t"></span>
      <button @click="todos.splice(i,1)">✕</button>
    </div>
  </template>

  <!-- x-if: only rendered when true -->
  <template x-if="todos.length === 0">
    <p>All done! 🎉</p>
  </template>

</div>

Forms & Two-Way Binding

x-model · .number · checkboxes · selects · textarea

EX 6.1 x-model — Two-Way Data Binding x-model · .number · .debounce ▼

x-model keeps an input and a reactive data property in sync in both directions — identical to Vue's v-model or React's controlled input pattern with onChange. Works on text, number, checkbox, radio, select, and textarea. Add .number to auto-cast to a Number type; .debounce.300ms to throttle updates.

HTML
<div x-data="{ name:'', age:18, agree:false, role:'dev' }">

  <input  type="text"     x-model="name"          />
  <input  type="number"  x-model.number="age"   />  <!-- casts to Number -->
  <input  type="checkbox" x-model="agree"        />

  <select x-model="role">
    <option value="dev">Developer</option>
    <option value="design">Designer</option>
  </select>

  <pre x-text="JSON.stringify({name,age,agree,role}, null, 2)"></pre>
</div>

Transitions & Animation

x-transition · enter/leave hooks · modal · toast · drawer

EX 7.1 x-transition — Animated Show / Hide x-transition · enter · leave ▼

Add x-transition to any x-show or x-if element for automatic fade+scale transitions. Use the fine-grained hooks x-transition:enter, x-transition:enter-start, x-transition:enter-end (and matching leave-* variants) to apply arbitrary CSS classes — similar to Vue's <Transition> component. The global toast above uses this pattern.

HTML
<!-- Default: fade + scale out of the box -->
<div x-show="open" x-transition>Content</div>

<!-- Custom hooks with CSS class names -->
<div x-show="open"
     x-transition:enter="transition ease-out duration-300"
     x-transition:enter-start="opacity-0 -translate-y-2"
     x-transition:enter-end="opacity-100 translate-y-0"
     x-transition:leave="transition ease-in duration-200"
     x-transition:leave-start="opacity-100"
     x-transition:leave-end="opacity-0"
>Slides in from top</div>

Magic Properties

$el · $refs · $watch · $nextTick · $dispatch

EX 8.1 $refs & $el — Direct DOM Access x-ref · $refs · $el ▼

Mark any element with x-ref="name" to access it imperatively via $refs.name — like React's useRef() or jQuery's $('#id'). $el always points to the component's root element. Use these when you need imperative DOM APIs: .focus(), .select(), canvas, video, etc.

HTML
<div x-data="{ copied: false }">

  <input x-ref="myInput" value="Hello Alpine!" />

  <button @click="
    navigator.clipboard.writeText($refs.myInput.value);
    copied = true;
    setTimeout(() => copied = false, 2000)
  ">
    <span x-text="copied ? '✓ Copied!' : 'Copy'"></span>
  </button>

  <!-- $el = the root <div> above -->
  <button @click="$refs.myInput.select(); $refs.myInput.focus()">Select All</button>

</div>
$refs clipboard demo
EX 8.2 $watch & x-init — Watching Changes $watch · x-init ▼

$watch('property', callback) fires a function whenever a data property changes — equivalent to Vue's watch() or React's useEffect([dep]). Set it up inside x-init, which runs once when the component mounts (like Vue's mounted() lifecycle hook).

HTML
<div
  x-data="{ score: 0, log: [] }"
  x-init="
    $watch('score', newVal => {
      log.unshift({ v: newVal, t: new Date().toLocaleTimeString() })
    })
  "
>
  <button @click="score += 10">+10 pts</button>
  Score: <span x-text="score"></span>
</div>

EX 8.3 $dispatch — Custom Events $dispatch · @custom-event.window ▼

$dispatch('event-name', payload) fires a native CustomEvent that bubbles up the DOM. Any ancestor can listen with @event-name. Use @event-name.window to listen globally — a clean way to communicate between components without a shared store.

HTML
<!-- Child dispatches a custom event -->
<button x-data
        @click="$dispatch('item-selected', { id: 42, name: 'Alpine' })">
  Select Item
</button>

<!-- Parent (or anywhere) listens with .window -->
<div x-data="{ selected: null }"
     @item-selected.window="selected = $event.detail">
  Selected: <span x-text="JSON.stringify(selected)"></span>
</div>

Global State

Alpine.store() · $store · Alpine.data()

EX 9.1 Alpine.store — Shared Reactive State Alpine.store · $store · alpine:init ▼

Alpine.store('name', data) registers global reactive state accessible from any component via $store.name — Alpine's lightweight equivalent of Vuex, Pinia, or React Context. Always register inside an alpine:init listener so stores are ready before Alpine processes the DOM.

JavaScript (before Alpine's <script> tag)
<script>
  document.addEventListener('alpine:init', () => {

    Alpine.store('cart', {
      items: [],
      add(item)  { this.items.push(item); },
      remove(id) { this.items = this.items.filter(i => i.id !== id); },
      get total() { return this.items.reduce((s, i) => s + i.price, 0); }
    });

    Alpine.store('toast', {
      visible: false, message: '',
      show(msg) {
        this.message = msg; this.visible = true;
        setTimeout(() => { this.visible = false; }, 2800);
      }
    });

  });
</script>
<script src="alpinejs.cdn.min.js" defer></script>

<!-- Access $store from any component on the page -->
<button x-data @click="$store.cart.add({ name: 'Item', price: 9.99 })">
  Add to cart (<span x-text="$store.cart.items.length"></span>)
</button>

EX 9.2 Alpine.data — Reusable Component Logic Alpine.data · x-data="name" ▼

Alpine.data('name', factory) registers a reusable data factory — like extracting a Vue component's data() function or a React custom hook. Reference it by string name inside x-data="name" to avoid duplicating logic across multiple elements.

JavaScript + HTML
<script>
  document.addEventListener('alpine:init', () => {

    Alpine.data('dropdown', () => ({
      open: false,
      toggle() { this.open = !this.open; },
      close()  { this.open = false; }
    }));

  });
</script>

<!-- Use by string reference — logic stays DRY -->
<div x-data="dropdown">
  <button @click="toggle()">Menu</button>
  <ul x-show="open" @click.outside="close()">
    ...
  </ul>
</div>

Directive

Directive

Directive

Directive
